# 从社区资料到 Direct Answer 的规则

整理日期：2026-11-07。重点是此前收集的 Astra / Sol 用户讨论、解决方案和开源项目。以下把资料中的观察、项目作者的案例和本项目的设计判断分开记录。

## 我们采用的判断方式

Direct Answer 把问题归纳为“句子对当前读者有什么用”。模型先确定用户的问题与实际主张，形成有依据的判断，再筛选限定语。

每项限定都要相关、具体且新增：说明它改变哪项判断，有什么实际影响，以及为何现在需要补充。这个三项检查是本项目对资料的综合设计，尚待行为实测。

以上社区材料提供设计线索，项目案例提供作者公开的局部对照。它们没有证明这套新规则的成功率。

## 保留的关键区别

- 用户的有限观察与模型自行推断的普遍结论分别处理。
- 未验证的扩展场景与已验证的局部结果分别处理。
- 删除重复免责与报告真实失败分别处理。
- 正面表达与事实纠错可以同时成立。
- 指令生效、宿主持续加载与实际回答改善分别验证。

规则由本项目重新组织和撰写；未将第三方完整提示词或代码复制进安装包。核心文件见 [SKILL.md](../skills/direct-answer/SKILL.md)，持续使用见 [continuity.md](../skills/direct-answer/references/continuity.md)。
